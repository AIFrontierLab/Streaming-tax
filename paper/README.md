# paper/: frozen item lists, expected numbers and audit labels

This folder ties runs of this code to the paper. It holds three kinds of small files, all derived by the paper's
authors and licensed with the rest of the repository (Apache-2.0):

- `frozen/`: the item lists, orders and seeds that fix *which* items an experiment uses;
- `expected/`: the paper's numbers, to compare a reproduction with;
- `flags/`: verdicts of the paper's audits, which qualify some cells of the analysis.

How to use them: [docs/reproducing-the-paper.md](../docs/reproducing-the-paper.md).

## Why there is no benchmark text and no model output here

- **Benchmark licences.** Several benchmarks are licensed for non-commercial or evaluation use only, are gated, or
  carry no licence at all, and LingoQA's licence forbids redistributing the data or anything derived from its text
  ([docs/licensing.md](../docs/licensing.md)). The lists here therefore hold item ids, row indices and sha256
  digests; texts, images and videos are rebuilt from your own copies of the data (`streamreplace download`,
  `streamreplace prepare`).
- **Model outputs and judge caches** repeat the prompts (benchmark text) and, for the safety benchmarks, contain
  harmful completions. They are not distributed. The expected numbers below are what those outputs produce.
- **Calibration texts** of the plugin (AdvBench, Stanford Alpaca) and the video clips cut from Video-MME are likewise
  referenced by index, video id and start time only.

| `plugin/full_items.json` | the 10,140 evaluation items of Stream++ (Sec. 6, Supp. D), outside the development slice and both pilots: Video-MME 666, TOMATO 1,225, TimeBlind 2,068, Video-SafetyBench 1,932, MCV-SafetyBench 2,656, VMDT fairness 1,146, VMDT privacy 447 | `plugin run / assemble / report --items full` | fixed list |

| `plugin/stream_pilot_items.json` | the 576 streaming-benchmark pilot rows (OVO-Bench 398, StreamingBench 178) pooled into each child's closed-choice threshold | `plugin run --arms sfix_prs --items stream_pilot`, `plugin calibrate --stage record --stream-pilot` | fixed list |

| `plugin/calibration_texts.json` | the 600 text inputs of the steering calibration as row indices into AdvBench and Alpaca (with the sha256 of the files they index), their labels and folds, and the `random.Random(0)` procedure that drew them | `plugin calibrate --stage directions` | the stated procedure, from your own copies |
| `plugin/calibration_videos.json` | the 300 Video-MME short videos in sha256 order (positions 0-95 fold 0, 96-143 fold 1) | `plugin calibrate --stage directions`, `--stage harmless` | the stated rule |

| `experiments/*.json` | the item lists of the diagnostic and supplementary experiments (ids only): `vmme750`, `vmme300` and `videomme666` (Video-MME questions of the window, memory and Recall controls), `parent_stream` and `timeblind_heldout` (parent controls), `safety_audit` (the response-form audit: HarmBench 510, Video-SafetyBench 800, MCV-SafetyBench 600), `vsb400_harmful`, `framing240`, `probe200`, `steering60`, `howto40` (Video-SafetyBench videos of the refusal analyses) | `streamreplace experiment ...` (`items:` of each experiment in `configs/experiments.yaml`) | fixed lists |

| `robustness/edits.json` | per perturbation condition: the number of rows, the sha256 of its `prompt_overrides.jsonl` and the skipped units | `robustness check --frozen` | `robustness edits` (paraphrases only with the paper's paraphrase cache) |
| `finetune/subset.json`, `train_order.json`, `selection.json` | the fine-tuning test subsets, the training orders (nested 1K/2K/5K prefixes) and the selection records (counts, dropped ids, hashes) | `finetune check`; `finetune prepare --frozen` copies them | `finetune prepare` |

"Fixed list" means the list is data: it records a choice made for the paper (a development slice, a pilot) that no
code derives from the benchmarks. The other lists are rebuilt by the command shown; `robustness check --frozen` and
`finetune check` compare a rebuild with the shipped copy.

## expected/

Extracted once from the paper's original runs and published tables; numbers only.

| File | Holds | Reproduced by |
|---|---|---|
| `contrasts.json` | the 334 P/C/S contrasts with the generation-cap reruns merged (every field: arms, delta, intervals, tests, Holm, TOST / NI, coverage, verdict, flags), the 20 contrasts left unreported because the stream arm answers none of the requests, the summary counts quoted in the text and the Video-MME S-C duration split | `streamreplace stats` |
| `contrasts_no_overlay.json` | the same on the formal rows only | `streamreplace stats --no-overlay` |
| `metrics.json` | the metrics and counts of each of the 235 formal jobs (the numbers behind the development report and the absolute-score tables) | `streamreplace report` |
| `tables.json` | the printed cell strings of Table 2, the MCV-SafetyBench table and the supplement's absolute-score (`eval_image`, `eval_video`, `eval_safety`, `eval_vmdt`), robustness (`eval_robustness`, `eval_instruction`) and fine-tuning (`eval_finetuning`, `eval_finetuning_gains`) tables | `streamreplace tables --check` (compares the written tables with this file cell by cell) |
| `plugin_recovery.json` | Stream++'s gate thresholds, the 54 recovery cells (6 children x 9 metrics, each with its contrasts), the means of Fig. 6, how the fixed refusal is scored on each benchmark, and the cells of the per-child figures | `streamreplace plugin report --items full` |

`tests/analysis/test_analysis_golden.py` checks these files against each other and, when the outputs folder holds the
paper's 235 scored jobs, recomputes the contrasts and metrics and compares them field by field. The documented
differences between the published paper and these numbers are listed in
[docs/reproducing-the-paper.md](../docs/reproducing-the-paper.md#known-differences-from-the-published-paper).

## flags/

Verdicts and shares from the paper's audits. `streamreplace stats` reads them to flag cells (docs/statistics.md,
"Flags"); without them those flags are simply not set.

| File | Holds | Used for |
|---|---|---|
| `response_forms.csv` | per safety benchmark split, child and transition (P->C, C->S, P->S): the verdict of an LLM-labelled response-form audit (less safe, safer, response-form change, no material change) | the `non_answer` flag of safety cells |
| `nonanswer_shares.csv` | per split, model and mode: the audited shares of non-answers, harmful help and refusal or safe deflection | the `non_answer` flag |
| `privacy_audit.csv` | per child and mode: the verdict of a manual audit of the VMDT privacy non-answers | the `non_answer` and `artifact` flags of privacy cells |
| `artifacts.csv` | cells whose replies depend on the judge's format handling | the `artifact` flag |

These are the paper's audit results. The response-form labelling itself can be rerun (`streamreplace experiment label
response_forms`, [docs/experiments.md](../docs/experiments.md)); the manual privacy audit cannot.
